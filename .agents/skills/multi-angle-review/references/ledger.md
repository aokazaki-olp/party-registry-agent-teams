# 台帳の書式

台帳は、レビューの**現在の状態と決定**の記録。読み手は台帳だけで「何が指摘され、人間が何を決め、いまどうなっているか」が分かること。

- **上書きで更新する。** 巡ごとに追記を重ねない。過去の状態は git の履歴と日次ログで追う
- **台帳の外に決定を置かない。** 人間の裁定は必ず台帳に書く。台帳から作業用ファイルを根拠として参照しない
- **書かないもの：** 経緯、統合役の較正や反省、調査の過程、議論の要約

---

## ID

- 形式：`<巡><観点の記号>-<番号>`。例 `1A-03` は第1巡・観点A の3番目
- 観点の記号は宣言で決める（A, B, C …）。検証役の指摘は `V`、修正中に見つかったものは `F`（例 `F-02`、巡を付けない）
- **番号を振り直さない。** 却下・保留・解消になっても ID は残す
- 複数の指摘を1つの ID にまとめない。同じ原因に見えるものは「同根候補」の列で互いを指す
- 一部だけ解消した指摘は、同じ ID のまま状態を「未解消」に戻し、残った部分を備考に書く

---

## 状態

| 状態 | 意味 | 誰が付けるか |
|---|---|---|
| 未判定 | 人間の決定がまだ無い | 統合役（転記時） |
| 採用 | 直すと人間が決めた | 人間 |
| 却下 | 直さないと人間が決めた。理由を必ず書く | 人間 |
| 保留 | 今は決めない。再開の条件を必ず書く | 人間 |
| 適用済 | 修正した。まだ確認されていない | 修正側（[[resolve-review-findings]]） |
| 解消 | 再レビューの検証役が解消と判定し、人間が確定した | 人間 |
| 未解消 | 再レビューで解消していないと判定された | 人間 |

統合役は、人間が言った決定を転記するだけで、自分では状態を進めない。

## 雛形

```markdown
---
type: review-ledger
target: <repo>/<path>
---

# <対象名> レビュー台帳

## 宣言

- 対象：<repo> / <path> / commit <hash>
- 基準（違反の根拠にしてよいもの）：
  - <文書パス> — <どの範囲が基準か>
- 参考扱い（違反の根拠にしないもの）：<文書パス>
- 範囲外：<見ないもの>
- 観点：A <名前と担当する失敗>、B …、C …
- 承認：<日付>

## 指摘

| ID | 場所 | 指摘（原文の要点） | 重大度 | 確信度 | 検証 | 同根候補・対立 | 状態 | 決定の理由・再開条件・備考 |
|---|---|---|---|---|---|---|---|---|
| 1A-01 | src/x.ts:42 | … | H | 高 | 成立：… | 1B-03 | 採用 | |

原文は `指摘原文/`、検証の全文は `検証/` にある。

## 巡

| 巡 | 日付 | commit | 新しい指摘 | 検証で成立 | 備考 |
|---|---|---|---|---|---|

## 収束

<人間が宣言したら書く。未収束で止めたなら、保留にした ID の一覧>
```

- 重大度：H＝正しさの欠陥・データの喪失、M＝保守性・整合性、L＝見た目・表現。レビュアーの申告を写し、人間が変えたらそれに合わせる
- 「指摘（原文の要点）」は原文から抜き出す。言い換えが要るほど長ければ、`指摘原文/` の該当箇所を指す
