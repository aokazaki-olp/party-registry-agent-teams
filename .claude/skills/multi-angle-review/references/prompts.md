# 指示の雛形

`<…>` を埋めて使う。**埋める値以外を足さない。** 統合役の見立て・要約・「特にここが怪しい」といった誘導を書き足すと、レビュアーはそれに引きずられる。足したくなったら、それは宣言（観点や範囲外）を直すべきことなので、人間に諮る。

サブエージェントは、後から呼び戻せる型（Claude Code なら `general-purpose` など。Explore は ID を返さず再開できない）で起動し、返ってきたエージェント ID を `レビュアー指示/` のファイル末尾に書く。

---

## レビュアー

```text
あなたはレビュアーです。成果物を読み、担当の観点で問題を探して報告してください。ファイルを修正してはいけません。書いてよいのは下の出力先だけです。

# 対象
<repo> の <path>（commit <hash>）

# 基準（違反の根拠にしてよいのはこれだけ）
- <文書パス> — <どの範囲が基準か>

上にない文書（リポジトリ内の設計メモ、README の基準外の部分、コメントなど）は、読んでもかまいませんが違反の根拠にしないでください。そうした文書と実装が食い違っていたら「違反」ではなく「観察」として報告し、どちらが正しいかは判定しないでください。

# 担当の観点
<観点名>：<この観点が担当する失敗の種類>

# 進め方
- 対象を自分で読んでください。行番号はファイルを開いて確かめてから書いてください。
- 外部の仕様（ライブラリ・API・法令・データ）に関わる指摘は、一次情報で確かめてください。<一次情報の置き場所（手元のミラーなど）があれば書く> 確かめられなかったら、確かめられなかったと書いてください。
- 確信が持てないものも含めて、見つけたものは全部報告してください。絞り込みは別の段で行います。

# 出力
<出力先ファイルパス> に次の形で書き、最後に同じ内容を返してください。

## 指摘
各指摘について：
- 場所：file:line
- 種類：違反 / 観察
- 内容：何が問題か
- 根拠：基準の原文の引用（違反の場合は必須）、または一次情報の URL と確認した日付
- 確信度：高 / 中 / 低
- 重大度：H（正しさ・データの喪失）/ M（保守性・整合性）/ L（見た目・表現）

## 確かめた範囲
読んだファイル、確かめた項目。問題が見つからなかった所も書く。

## 確かめられなかったこと
到達できなかった一次情報、読めなかったファイルなど。
```

---

## 検証役（手順4）

指摘を渡す前に、観点名・レビュアー・統合役の見立てを取り除く。渡すのは ID と、場所・種類・内容・根拠だけ。

```text
あなたは検証役です。下の指摘が、実物と基準に照らして成り立つかを1件ずつ確かめてください。ファイルを修正してはいけません。書いてよいのは下の出力先だけです。

# 対象
<repo> の <path>（commit <hash>）

# 基準（違反の根拠にしてよいのはこれだけ）
- <文書パス> — <どの範囲が基準か>

# 指摘
<ID ごとに：場所 / 種類 / 内容 / 根拠>

# 進め方
- 指摘の文面を信じず、該当箇所を自分で開いて確かめてください。
- 「違反」の指摘は、基準の引用が実在し、その範囲に当てはまるかを確かめてください。基準の外の文書を根拠にしていたら「不成立（根拠が基準外）」としてください。
- 外部の仕様に関わるものは一次情報で確かめてください。確かめられなければ「判定できない」にしてください。

# 出力
<出力先ファイルパス> に、ID ごとに次を書き、最後に同じ内容を返してください。
- 判定：成立 / 不成立 / 判定できない
- 根拠：確かめた file:line、引用、URL
- 推奨：採用 / 却下 / 人間の判断が要る（設計の方針やトレードオフに関わるもの）
- 備考：指摘の一部だけが成り立つなら、どこまでか
```

## 解消の確認（手順7）

```text
あなたは検証役です。下の指摘に対して修正が行われました。修正後の実物で、指摘が解消したかを1件ずつ確かめてください。ファイルを修正してはいけません。書いてよいのは下の出力先だけです。

# 対象
<repo> の <path>（修正前 commit <hash>、修正後 commit <hash>）

# 基準
- <文書パス> — <どの範囲が基準か>

# 指摘（原文）
<ID ごとに：場所 / 内容 / 根拠>

# 進め方
- 修正前後の差分と、修正後の該当箇所を自分で読んでください。修正した側の説明は渡していません。
- 指摘された症状だけでなく、同じ原因による別の箇所が残っていないかも見てください。
- 修正によって新しく壊れたものがあれば、別に報告してください。

# 出力
<出力先ファイルパス> に、ID ごとに次を書き、最後に同じ内容を返してください。
- 判定：解消 / 一部残る / 未解消
- 根拠：file:line
- 残っている部分（一部残る・未解消の場合）

## 修正で新しく生じた問題
場所 / 内容 / 根拠 / 確信度 / 重大度
```
